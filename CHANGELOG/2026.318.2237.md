opencharly/spec#322 collapsed the load wire: `#StructuralKindLoadEnv.members` carries bytes and `#StandaloneLoad` carries `shape` plus ONE opaque `body`, so the authored `#Deploy` / `#Box` / `#Candy` / typed-`template` arms are gone.

This plugin follows it — and the one place it threads authored members now DECODES them from bytes into the contract's projection before they join the ordered tree (visible in `plugin.go`, covered by `TestInvokeReconstructsMemberTree`). Nothing about the wire's discriminator moved: `shape` keeps its four values, so the arm still selects by shape and only the carrier changed.

**Why this shape and not a compatibility field:** the RCA (`PROGRAM/schema-ownership-rca-rdd.md`) found the wire was what kept ten authored bodies in the contract. Its mechanism is one carrier of bytes plus a projection — the plugin never receives the authored node.

Pins brought current to the cutover: `spec v0.2026318.2106`, `sdk v0.2026318.1654` (the `sdk` bump is load-bearing: its `cueKindDefs` still named `#Vm`).
